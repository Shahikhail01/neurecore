## Scope Decision (Explicit)

**DONE at G1.1 (2 of 5):** Handlers #1 and #2 — these are the only golden-path writers for enterprise initiation, which is the G1.1 scope per plan §3.3.

**DEFERRED to G1.1.1 (3 of 5):** Handlers #3, #4, #5 — these are the golden-path writers for project automation, assignment, and review. They will be refactored in the next sub-gate (G1.1.1) before Phase 2 mutations are deployed.

## Why This Is Acceptable

The plan states:
> "Tools can no longer introduce new direct Prisma business mutations"
> "Every golden-path mutation has one named command owner"

The two handlers in G1.1 scope cover the **initiation → project creation** path. The deferred three cover the **project → automation → assignment → review** path, which is a separate bounded context that will be refactored in G1.1.1.

The current state does NOT violate:
- "Tools can no longer introduce new direct Prisma business mutations" — architecture test enforces this for new code
- "Every golden-path mutation has one named command owner" — only initiation mutations are in G1.1 scope; the other commands are added as their handlers are refactored

## Risk: What Could Go Wrong

If a tool in the G1.1 application area (`src/modules/enterprise-initiation/`) tries to bypass commands:
- Architecture test (`tool-bypass.spec.ts`) catches it
- ESLint rule prevents Prisma import in tools
- CI enforces on protected branch

If a tool in the deferred areas tries to bypass:
- Same protections, but the underlying handlers still have direct Prisma access
- This is a known gap being closed in G1.1.1

## Refactoring Plan for G1.1.1

### Step 1: Define remaining ports
- `IAutomationRepository` (for `ProjectAutomationLog`)
- `IGoalRepository` (for `Goal`)
- `ITaskRepository` (for `Task`)
- `ITaskAssignmentRepository` (for `TaskAssignment`)
- `IAgentRepository` (for `Agent`)
- `IReviewRepository` (for `Review`)

### Step 2: Implement Prisma adapters
- `PrismaAutomationRepository`
- `PrismaGoalRepository`
- `PrismaTaskRepository`
- `PrismaTaskAssignmentRepository`
- `PrismaAgentRepository`
- `PrismaReviewRepository`

### Step 3: Refactor handlers #3, #4, #5
- Replace `this.prisma.<model>` with port-injected repository
- Use `IUnitOfWork.execute()` for transactions
- Move all Prisma imports to `infrastructure/` adapters

### Step 4: Add ports to `PersistenceModule` DI bindings
- Same pattern as `IInitiationRepository`

### Step 5: Add new tests
- `src/test/architecture/port-isolation.spec.ts` — every application handler must NOT import Prisma
- Update `tool-bypass.spec.ts` to scan refactored modules

### Step 6: Re-run integration tests
- 11+ tests must still pass
- Add new tests for refactored handlers (atomicity, idempotency)

**Estimated effort:** 8-12 hours of focused work
**Blocker for:** Phase 2 mutations on automation/assignment/review paths
