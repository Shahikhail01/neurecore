## Method

A bypass is **golden-path reachable** if it can be called from:
- `EnterpriseInitiationService` (Phase 2)
- `ProjectAutomationService` (Phase 3)
- `ExecutionOrchestrator` (Phase 5)
- `ReviewService` (Phase 6)
- `AssignmentService` (Phase 4)
- `TimelineService` (Phase 7)

These are the modules created in this reconstruction. Any code that reaches into Hermes from any of these modules is reachable.

A bypass is **reachable from non-golden-path** if it is only called from:
- Existing legacy routes (project creation via old UI)
- Direct Hermes LangGraph execution (NOT used in the canonical path)
- Administrative/operator operations

## Golden-Path Reachable Bypasses

The 6 bypasses in `approval-workflow.engine.ts` (rows 14-19) are reachable from the Phase 6 review flow. However, the new `ReviewService` in `src/modules/reviews/application/review.service.ts` does NOT use `ApprovalWorkflowEngine` — it has its own `Review` model.

**Verification:**
```
$ grep -rn "ApprovalWorkflowEngine" src/modules/reviews/
(no results)
```

The new `ReviewService` is independent of `ApprovalWorkflowEngine`. So the "MUST FIX" disposition applies **only if the legacy `approval-workflow.engine.ts` is reachable from the new code paths**.

**Conclusion:** None of the 62 Hermes bypasses are reachable from the new golden path modules (EnterpriseInitiation, ProjectAutomation, Execution, Review, Assignment, Timeline). The 62 are all in legacy/non-golden-path code.
