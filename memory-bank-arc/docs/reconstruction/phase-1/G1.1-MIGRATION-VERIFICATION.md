# G1.1 — Migration Verification Procedure

**Date:** 2026-07-26
**Status:** Pending — requires isolated environment

## Why This Document Exists

The previous G1 evidence claimed the migration was "ready" but never verified it against a real database. This document specifies the **exact steps** to verify the migration in an isolated environment before G1.1 can pass.

## Required Environment

- Isolated PostgreSQL 15+ instance
- Pre-migration schema (or clean database)
- Backup capability
- Prisma CLI 5.22.0+
- Connection string with full privileges

## Pre-Migration Checklist

- [ ] Database backed up
- [ ] Migration file reviewed: `prisma/migrations/20260726_autonomous_work_layer/migration.sql`
- [ ] `prisma migrate status` returns no pending migrations
- [ ] No active connections that would block schema changes

## Migration Application Steps

```bash
# 1. Set environment
export DATABASE_URL="postgresql://user:pass@host:5432/awl_reconstruction"

# 2. Verify pre-state
psql $DATABASE_URL -c "SELECT table_name FROM information_schema.tables WHERE table_schema = 'public' ORDER BY table_name;" > /tmp/tables_before.txt

# 3. Apply migration
npx prisma migrate deploy

# 4. Verify post-state
psql $DATABASE_URL -c "SELECT table_name FROM information_schema.tables WHERE table_schema = 'public' ORDER BY table_name;" > /tmp/tables_after.txt
diff /tmp/tables_before.txt /tmp/tables_after.txt

# 5. Verify new tables exist
psql $DATABASE_URL -c "\d enterprise_initiations" > /tmp/enterprise_initiations.txt
psql $DATABASE_URL -c "\d execution_attempts" > /tmp/execution_attempts.txt
psql $DATABASE_URL -c "\d reviews" > /tmp/reviews.txt
psql $DATABASE_URL -c "\d evidence_artifacts" > /tmp/evidence_artifacts.txt
psql $DATABASE_URL -c "\d task_assignments" > /tmp/task_assignments.txt
psql $DATABASE_URL -c "\d tenant_feature_flag_overrides" > /tmp/tenant_feature_flag_overrides.txt
psql $DATABASE_URL -c "\d feature_flag_audit_logs" > /tmp/feature_flag_audit_logs.txt

# 6. Verify new columns on existing tables
psql $DATABASE_URL -c "\d goals" | grep -E "automationVersion|templateKey"
psql $DATABASE_URL -c "\d tasks" | grep -E "automationVersion|templateKey|requiredRole|requiredCapabilities"
psql $DATABASE_URL -c "\d agents" | grep -E "role|capabilities|maxConcurrency|availability|archived"
psql $DATABASE_URL -c "\d projects" | grep -E "executionEngineVersion|initiationId"
psql $DATABASE_URL -c "\d audit_logs" | grep -E "correlationId|causationId"

# 7. Verify unique constraints
psql $DATABASE_URL -c "SELECT indexname, indexdef FROM pg_indexes WHERE tablename IN ('goals', 'tasks') AND indexname LIKE '%unique%';"

# 8. Test rollback
npx prisma migrate resolve --rolled-back 20260726_autonomous_work_layer
# Verify tables are gone
psql $DATABASE_URL -c "\dt enterprise_initiations" 2>&1 | grep -q "Did not find" && echo "Rollback verified" || echo "Rollback FAILED"

# 9. Re-apply
npx prisma migrate deploy
```
